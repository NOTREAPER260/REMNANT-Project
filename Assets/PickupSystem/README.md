# Pickup System — လမ်းညွှန်

ဘယ် object ကိုမဆို **E နှိပ်ပြီး ကောက်ယူလို့ရအောင်**၊ inventory ထဲမှာ **အဲဒီ object ရဲ့ တကယ့်ပုံစံအတိုင်း ပေါ်အောင်**၊
ပြီးရင် **G နှိပ်ပြီး ပြန်ချလို့ရအောင်** လုပ်ပေးတဲ့ system ပါ။

ပုံဆွဲစရာ၊ prefab ဆောက်စရာ၊ package ထည့်စရာ ဘာမှ မလိုပါဘူး။

---

| ဖိုင် | ဘယ်မှာ တင်ရမလဲ | ဘယ်နှစ်ခု |
|---|---|---|

| `Door.cs` | **ဖွင့်ချင်တဲ့ တံခါးတိုင်း** ပေါ်မှာ | တံခါးတစ်ချပ်လျှင် တစ်ခု |

## ၁။ `Pickup.cs` — ပစ္စည်းတစ်ခုချင်းစီပေါ်မှာ တင်ရမယ့်ဟာ

ဒါက **သင် အများဆုံး သုံးရမယ့် ဖိုင်**ပါ။ ကောက်ချင်တဲ့ object ပေါ်မှာ တင်လိုက်ရုံနဲ့ ပြီးပါပြီ။

**လိုအပ်ချက် ၂ ခု —** အဲဒီ object မှာ

1. **Renderer** ရှိရမယ် (မမြင်ရတဲ့ object ကို ပုံရိုက်လို့ မရလို့ပါ)
2. **Collider** ရှိရမယ် (ray နဲ့ ချိန်ရလို့ပါ) — မရှိရင် `Reset()` က `BoxCollider` ကို အလိုအလျောက် ထည့်ပေးပါတယ်

**Inspector မှာ ချိန်လို့ရတာတွေ**

| Field | ဘာလဲ |
|---|---|
| `Item Name` | Inventory မှာ ပြမယ့် နာမည်။ **အင်္ဂလိပ်လိုပဲ ရေးပါ** (အောက်က မှတ်ချက်ကို ကြည့်ပါ)။ Component ထည့်လိုက်တာနဲ့ GameObject နာမည်အတိုင်း အလိုလို ဝင်ပါတယ် |
| `Description` | Inventory အောက်ခြေမှာ ပြမယ့် အသေးစိတ် |
| `Icon Override` | ကိုယ်ပိုင် Sprite သုံးချင်ရင် ထည့်ပါ။ **ဗလာထားရင် object ကိုယ်တိုင်ကို ပုံရိုက်ပါတယ်** |
| `Icon Size` | ပုံရဲ့ pixel အရွယ် (64–512၊ default 192) |
| `Icon Rotation` | ပုံရိုက်တဲ့ ထောင့်။ **ပုံမမှန်ရင် အရင်ဆုံး ဒါကို ချိန်ကြည့်ပါ** |
| `Icon Padding` | ပုံရဲ့ ဘေးမှာ ချန်မယ့် နေရာ (1 = တင်းတင်းကပ်) |
| `Pickup Sound` | ကောက်တဲ့အခါ မြည်မယ့် အသံ (မထည့်လည်း ရ) |

### `Icon Rotation` ကို ဘယ်လိုချိန်ရမလဲ

Camera က object ကို **+Z ဘက်ကို ကြည့်နေတာ**ပါ။ ဒါကြောင့် object ရဲ့ ဘယ်မျက်နှာကို ပြချင်လဲဆိုတာပေါ်မူတည်ပြီး လှည့်ပေးရပါတယ်။

- **စာအုပ်လို ပြားပြားပစ္စည်း** — အဖုံးကို ပြချင်ရင် X ကို `-90` ဝန်းကျင်။ Book မှာ `(-55, -35, 8)` သုံးထားပါတယ် (အထူကိုပါ မြင်ရလို့)
- **ဓာတ်မီးလို ရှည်မှောင်တဲ့ပစ္စည်း** — `(18, -28, 0)` လို 3/4 ထောင့်က ကောင်းပါတယ် (ဒါက default ပါ)

## ၂။ `PlayerInteractor.cs` — Scene တစ်ခုလျှင် တစ်ခုတည်း

ကင်မရာရှေ့ကို ray ပစ်ပြီး `Pickup` တွေ့ရင် အောက်မှာ `[ E ]  နာမည်` လို့ ပြပေးတယ်။ E နှိပ်ရင် inventory ထဲ ထည့်ပေးတယ်။
မြင်ကွင်းအလယ်က **အစက်လေး (crosshair)** ကိုလည်း ဒီ script က ဆောက်ပေးတာပါ။

`Camera.main` ကို အလိုအလျောက် ရှာလို့ ဘယ် GameObject ပေါ်တင်တင် ရပါတယ်။
လက်ရှိမှာ **`Inventory System`** ပေါ်မှာ တင်ထားပြီး `Inventory` ကို ချိတ်ပြီးသားပါ။

| Field | ဘာလဲ |
|---|---|
| `Inventory` | ဗလာထားရင် scene ထဲက `HorrorInventory` ကို အလိုလိုရှာပါတယ် |
| `Eyes` | ဗလာထားရင် `Camera.main` |
| `Interact Key` | Default `E` |
| `Reach` | ဘယ်လောက်ဝေးအထိ ကောက်လို့ရလဲ (default 3) |
| `Aim Assist Radius` | ray လွဲသွားရင် ခွင့်လွှတ်ပေးမယ့် အတိုင်းအတာ |
| `Blocking Layers` | ဘယ် layer တွေက ray ကို ပိတ်ဆို့လဲ |

**နံရံကြားကနေ ကောက်လို့မရပါဘူး** — ray ရဲ့ ရှေ့ဆုံးအရာက `Pickup` မဟုတ်ရင် အဲဒီနေရာမှာ ရပ်သွားပါတယ်။
ကစားသမားကိုယ်တိုင်ရဲ့ collider ကတော့ ကျော်သွားပါတယ်။

## ၂.၅။ `Door.cs` — တံခါးတစ်ချပ်ချင်းစီပေါ်မှာ

E နှိပ်ရင် ဖွင့်/ပိတ်လုပ်ပေးပါတယ်။ **Animation clip မလိုပါဘူး** — code နဲ့ တဖြည်းဖြည်း
လှည့်ပေးတာမို့ ဘယ် တံခါး mesh မဆို setup မလိုဘဲ အလုပ်လုပ်ပါတယ်။

| Field | ဘာလဲ |
|---|---|
| `Display Name` | Prompt မှာ ပြမယ့် နာမည် (`OPEN   DOOR`) |
| `Open Angle` | ဘယ်လောက် ဟမလဲ (default 95°) |
| `Open Duration` | ဖွင့်ချိန် စက္ကန့် (default 0.7) |
| `Hinge Axis` | အထစ်ဝင်ရိုး၊ တံခါးရဲ့ local space (ပုံမှန် Y) |
| `Facing Axis` | တံခါးမျက်နှာမူရာ။ **သုည ထားရင် mesh ကနေ အလိုအလျောက် တွက်ပါတယ်** |
| `Open Away From Player` | ကစားသမားဘက်ကို မလှည့်ဘဲ တစ်ဖက်ကို ဟပေးတယ် |
| `Locked` | ပိတ်ထားရင် `LOCKED` လို့ပဲ ပြပြီး မဖွင့်ပါဘူး |
| `Open/Close/Locked Sound` | အသံ (မထည့်လည်း ရ) |

### ⚠️ Pivot က အထစ်အနားမှာ ရှိရပါမယ်

တံခါးရဲ့ pivot က **အလယ်မှာ ရှိနေရင် အလယ်ပတ်လည် လှည့်သွား**ပါလိမ့်မယ်။

**ဒါ့အပြင် —** တံခါး (ဒါမှမဟုတ် သူ့ parent) မှာ **scale မညီညာ (non-uniform) ဖြစ်နေရင်
လှည့်တဲ့အခါ တံခါးက ပုံပျက်သွား**ပါတယ်။ ဒါက Unity ရဲ့ transform စနစ်ရဲ့ သဘောပါ။

နှစ်မျိုးလုံးအတွက် ဖြေရှင်းနည်းက တူပါတယ် — **empty GameObject တစ်ခုကို
အထစ်နေရာမှာ၊ scale (1,1,1) နဲ့ ထားပြီး တံခါးကို အဲဒီအောက် ထည့်ပါ။
ပြီးရင် `Door` ကို အဲဒီ empty ပေါ်မှာ တင်ပါ။**

Scene ထဲက Interior door ၄ ချပ်ကို အဲဒီနည်းနဲ့ ပြင်ထားပြီးပါပြီ
(`Interior_Door_Hinge` စသဖြင့် pivot object တွေ ဆောက်ထားပါတယ်)။

## ၂.၇။ `IInteractable.cs` — မတင်ရပါ (interface)

E နှိပ်လို့ရတဲ့ အရာအားလုံးရဲ့ စံပါ။ `Pickup` ရော `Door` ရော ဒါကို implement လုပ်ထားလို့
`PlayerInteractor` က တစ်ခုတည်းနဲ့ နှစ်မျိုးလုံးကို ကိုင်တွယ်နိုင်တာပါ။

အသစ်တစ်မျိုး (ခလုတ်၊ အံဆွဲ၊ မီးခလုတ်) လုပ်ချင်ရင် ဒါကို implement လုပ်လိုက်ရုံနဲ့
E နဲ့ အလုပ်လုပ်သွားပါလိမ့်မယ် — `PlayerInteractor` ကို ပြင်စရာ မလိုပါဘူး:

```csharp
public class Lever : MonoBehaviour, IInteractable
{
    public string Prompt      { get { return "PULL   LEVER"; } }
    public bool   CanInteract { get { return true; } }
    public string Interact(GameObject interactor) { /* ... */ return null; }
}
```

## ၃။ `ObjectPreviewRenderer.cs` — မတင်ရပါ (Pickup က အလိုလိုခေါ်ပါတယ်)

Object ကို **ဓာတ်ပုံရိုက်ပြီး Sprite အဖြစ် ပြောင်းပေးတဲ့** utility ပါ။ `Pickup` က icon လိုတဲ့အခါ ကိုယ်တိုင် ခေါ်သုံးပါတယ်။
တစ်ခါရိုက်ပြီးရင် မှတ်ထားလို့ ထပ်ခါထပ်ခါ မရိုက်ပါဘူး။

**ဘာကြောင့် ရှုပ်ရှုပ်ထွေးထွေး လုပ်ထားရလဲ —** အောက်ပါ ၃ ချက်က ပြဿနာကို ကြိုကာကွယ်ထားတာပါ:

1. **Scene အောက် ၉၀၀၀ unit မှာ ရိုက်တယ်** — မူရင်း object ကို ကူးယူပြီး ဂိမ်းကင်မရာ ဘယ်တော့မှ မမြင်နိုင်တဲ့နေရာမှာ ထားလိုက်တာပါ။ မူရင်း object ကို လုံးဝ မထိပါဘူး
2. **Scene ထဲက မီးအားလုံးကို ခဏပိတ်တယ်** — မဟုတ်ရင် မှောင်တဲ့နေရာမှာ ကောက်ရင် icon မှောင်၊ လင်းတဲ့နေရာမှာ ကောက်ရင် icon လင်း ဖြစ်နေမှာပါ။ ရိုက်ပြီးတာနဲ့ ချက်ချင်း ပြန်ဖွင့်ပေးပါတယ် (`try/finally` နဲ့ ထိန်းထားလို့ error တက်လည်း မီးပိတ်ကျန်မှာ မဟုတ်ပါ)
3. **နောက်ခံ အနက်နဲ့ အဖြူ နှစ်ခါရိုက်တယ်** — ကွာခြားချက်ကနေ alpha ကို တွက်ထုတ်တာပါ။ render pipeline က alpha ကို ဘယ်လိုကိုင်တွယ်တွယ် နောက်ခံ ဖောက်ထွင်းမြင်ရဖို့ အာမခံပါတယ်

## ၄။ `Editor/PickupSystemMenu.cs` — မတင်ရပါ (menu item)

Unity ရဲ့ menu bar မှာ ပေါ်ပါတယ်:

- **`Tools → Pickup System → Make Selected Pickable`**
  ရွေးထားတဲ့ object တွေမှာ `Collider` + `Pickup` ကို ထည့်ပေးပြီး နာမည်ဖြည့်ပေးတယ်။ တစ်ခါတည်း အများကြီး ရွေးလို့ ရပါတယ်
- **`Tools → Pickup System → Make Selected Doors`**
  ရွေးထားတဲ့ တံခါးတွေမှာ `Collider` + `Door` ကို ထည့်ပေးတယ်
- **`Tools → Pickup System → Add Interactor To Scene`**
  `PlayerInteractor` ကို scene ထဲ ထည့်ပေးတယ် (ရှိပြီးသားဆိုရင် အဲဒါကို ညွှန်ပြပေးတယ်)

## ပစ္စည်းအသစ်တစ်ခု ထည့်ချင်ရင် (အဆင့် ၃ ဆင့်)

2. `Tools → Pickup System → Make Selected Pickable`

ပြီးပါပြီ။ `Ctrl+S` သိမ်းလိုက်ပါ။

`HorrorInventory` ရဲ့ Inspector မှာ အသုံးဝင်တာတွေ — `Slot Count` (slot ဘယ်နှစ်ခု)၊ **`UI Scale`** (panel နဲ့ စာလုံး အားလုံးကို တစ်ပြိုင်နက် ကြီး/သေး)၊ `Drop Key` (default `G`)၊ `Drop Distance`။

## သိထားသင့်တဲ့ အချက်များ

**စာသားတွေ အင်္ဂလိပ်လိုပဲ ရေးပါ။**
Unity ရဲ့ uGUI (နဲ့ TextMeshPro) က မြန်မာစာကို မှန်မှန်ကန်ကန် မဖော်ပြနိုင်ပါဘူး — `ေ` နဲ့ `ြ` လို သင်္ကေတတွေရဲ့ နေရာက လွဲသွားပါတယ်။
UI Toolkit တစ်ခုတည်းသာ ရပါတယ်။ ဒါကြောင့် `Item Name` နဲ့ `Description` ကို အင်္ဂလိပ်လိုပဲ ရေးပါ။

**ကောက်လိုက်တဲ့ object ကို မဖျက်ပါဘူး — ဝှက်ထားရုံပါ။**
ဒါကြောင့် ကောက်ထားသမျှ **အားလုံး ပြန်ချလို့ရပါတယ်**။ ပြန်ချတဲ့အခါ အဲဒီ object ကိုပဲ ပြန်ဖွင့်ပေးလို့ mesh, material, children အားလုံး အတိအကျ တူပါတယ်။

**ဓာတ်မီးကတော့ ဘယ်တော့မှ ချလို့မရပါဘူး။**
ဓာတ်မီးက `Pickup` ကနေ လာတာ မဟုတ်ဘဲ `HorrorInventory` ကိုယ်တိုင် ဖန်တီးထားတာမို့ ချစရာ world object မရှိပါဘူး။
G နှိပ်ရင် `CAN NEVER BE DROPPED` လို့ ပြပါလိမ့်မယ်။

**Icon က object ရဲ့ လက်ရှိအသွင်အပြင်အတိုင်းပါ။**
Object မှာ material အသစ်တစ်ခု ပေးလိုက်ရင် icon လည်း **အလိုအလျောက် လိုက်ပြောင်း**ပါလိမ့်မယ် — ပုံအသစ် ပြန်ဆွဲစရာ မလိုပါဘူး။

**ဒီ system က asset တစ်ခုမှ import မလုပ်ပါဘူး။**
Panel, ဘောင်, icon အားလုံးကို runtime မှာ code နဲ့ ဆွဲထုတ်တာမို့ project ထဲကို ဖိုင်အသစ် ဝင်လာမှာ မဟုတ်ပါဘူး။
